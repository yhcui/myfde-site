Token 经济学：AI 应用的成本控制

把 token 当预算管理：五个降本杠杆（缓存、模型路由、批量、上下文瘦身、蒸馏），先度量再优化的顺序，和不该省的地方。

心法

API 计费三本账：输入 token、输出 token、缓存命中——三条价各不相同，输出通常远贵于输入，命中缓存的长前缀按折扣计。不懂这个结构，优化就只会「换便宜模型」这一招。

以及一条纪律：先度量，再优化。没有分环节的成本记录，你连「钱花在哪」都不知道——多数人优化的是最贵的环节，而不是最浪费的环节。

五个降本杠杆

杠杆原理难度注意
提示词缓存固定长前缀只完整处理一次低不变内容放前、可变内容放后（见《上下文工程》）
模型路由简单任务用小模型，难题才上旗舰中分级路由规则要用评估集验证，别拍脑袋
批量接口离线任务走批处理折扣价低只适合不赶时间的任务
上下文瘦身窗口里每 token 都在计费低清洗工具结果、压缩历史——最被低估的杠杆
蒸馏用大模型输出训练小模型顶常规任务高适合超大量、模式固定的场景（见术语表）

性价比排序：上下文瘦身和缓存几乎白拿钱，先做；路由次之；蒸馏最后再说。

先度量：三个必装仪表

  1. 按环节记账：检索注入多少、系统提示多少、历史多少、输出多少——分桶统计；
  2. 按任务记账：哪类请求花掉大头；
  3. 单价联动：token 单价会变，账要按「token 量」记而不是「金额」记。

不该省的三个地方

  • 评估集的钱：省它等于闭眼开车（见《Evals》）；
  • 输出质量的底线：降本以核心场景通过率红线为界，破线回滚；
  • 日志与留痕：出事故时没有留痕，赔偿与复盘的成本远超存储费。

一句话

成本控制不是「换便宜的」，是把贵的 token 花在刀刃上——固定内容进缓存、可压缩内容先压缩、简单任务降级、核心任务保满配。
