LangChain / AutoGen / CrewAI 怎么选

主流 Agent 框架横评：先决定要不要框架，再看三家各自的强项与代价，附场景决策表和一条保命原则。

第一个问题不是选哪家，是要不要

框架解决的是「别重复造轮子」：模型调用、工具挂载、记忆、编排都有现成抽象。代价是抽象层的学习成本和升级追赶——这个领域框架迭代极快，去年的最佳实践今年可能重写。

判断：学习期、原型期用框架（快）；核心生产链路自己写薄封装（稳）——直接调模型 API + 你自己的几百行编排代码，往往比绕框架抽象更好调试。框架会过时，协议（如 MCP）与原理（工具调用、上下文、评估）不会。

三家横评

LangChain / LangGraphAutoGenCrewAI
出身开源社区主流微软研究院开源社区
核心抽象链 / 图编排（LangGraph）多 Agent 对话角色 + 任务
强项生态最全：集成、RAG、观测一应俱全多 Agent 协作研究味浓，事件驱动上手最快，「 Crew（班组）」心智直观
代价抽象层厚，出错时栈深文档与工程化打磨一般灵活性上限低，复杂逻辑别硬塞
适合快速原型 + 需要 RAG/观测全家桶多 Agent 实验、研究型项目三五角色的小型流水线

场景决策表

  • 「我要两周做个内部问答」→ LangChain（RAG 组件全）
  • 「我要验证写-审分离能不能提质」→ AutoGen
  • 「我就要个固定的 调研→写作→发布 小流水线」→ CrewAI
  • 「这是要上线收费的核心服务」→ 薄封装自写，或框架仅用于外围、核心循环自控

一条保命原则

无论选谁，把「模型调用、工具定义、评估集」三个接口留在自己手里，与框架解耦：换框架那天，你的资产（工具、数据、评估）原封不动。评估集尤其重要——它是你比较「框架 A vs 框架 B」唯一的客观裁判（见《Evals》）。

选型之后的路径

选定后按这个顺序推进，别跳步：单工具跑通 → 多工具循环 → 加记忆与检索 → 加评估与护栏 → 多 Agent。每一节的展开在本栏目的系列文章里，从《AI Agent 入门指南》开始读。
