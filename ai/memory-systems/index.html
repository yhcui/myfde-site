Agent 的记忆系统：记住该记的，忘掉该忘的

记忆不是把历史全塞进窗口：三类记忆（会话草稿/结构化事实/长期检索）、记住什么忘掉什么的判断标准、以及记忆效果的评估方法。

为什么记忆是个设计问题

窗口有限、历史无限、token 按量计费——这三条决定了「全记住」不可行。记忆系统的本质是压缩与取舍：把对话流提炼成对后续任务有用的状态。

三类记忆，各司其职

类型存什么生命周期载体
会话草稿（短期）当前任务的中间状态单次会话窗口内 + 滚动摘要
结构化事实（中期）用户偏好、约束、关键参数跨会话键值存储，按需注入
长期知识（长期）历史沉淀的资料与结论永久向量库（RAG 检索）

关键认知：大多数「记忆」问题其实是信息分类问题——决定一条信息属于哪一类，比选择记忆框架重要得多。

记什么：三个保留判据

一条信息值得进入结构化记忆，当且仅当：

  1. 跨会话有用：下次对话还会影响行为（用户的格式偏好、业务约束）；
  2. 改变决策：记住它与否会让后续回答不同（客户的项目名称、已确认的方案）；
  3. 来源明确：能标注「谁在什么时候说的」——无法溯源的「记忆」是幻觉的温床。

三条不满足就让它留在会话层，会话结束自然蒸发。

怎么记：结构化优于自然语言

把「用户叫王工，负责采购流程，喜欢表格输出」存成字段，而不是存整段对话摘要。注入时按需取用，字段级记忆可控、可编辑、可审计；自然语言摘要三者皆不可控。

对话过长时的滚动压缩：每 N 轮把早期对话总结进结构化字段，原文出窗。压缩本身有损，所以摘要只保留事实与决策，语气与过程丢弃。

记忆的遗忘

记忆不是只进不出的堆栈：

  • 过期淘汰：带时间戳的约束（「本月预算 5 万」）到期自动失效或要求确认；
  • 冲突覆盖：新事实显式覆盖旧字段，并保留版本痕迹；
  • 用户可查可删：能被用户查看和清除的记忆才是合规的记忆——这也是数据法规的硬要求。

怎么评估记忆有没有用

加两对照测试进评估集（见《Evals》）：

  • 该记的记住了吗：跨会话场景题（第一天说了偏好，第三天还在遵守吗）；
  • 不该记的忘了吗：过期约束题（上月的预算限制这个月还生效就是 bug）。

记忆系统的每一分复杂度都要用这两题的收益来换——答不上来的记忆层，是给自己加的调试负担。
