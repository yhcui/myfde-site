## 两条路线的本质区别

| | 一体机方案 | 自建集群 |
|---|---|---|
| 形态 | 厂商预集成：卡+推理+软件栈打包 | 自选硬件 + 自建推理栈与调度 |
| 上线速度 | 天级 | 周到月级 |
| 运维 | 厂商兜底（响应看合同） | 自建团队（响应看你自己） |
| 能力上限 | 单机天花板 | 可横向扩 |
| 升级 | 跟厂商版本走 | 自主但有完整成本 |
| 成本结构 | 一次性高、后续按服务合同 | 一次硬件 + 持续人力 |

一句话：**一体机买的是「确定性」，集群买的是「自由度」**——价格都是这两种价值的影子。

## 三条判断原则

**1. 看组织有没有运维人手。**
现场没有专职运维的（大多数传统企业客户），一体机的「厂商兜底」不是懒政是刚需——自建集群交给没有 GPU 运维经验的团队，第一年的事故成本被严重低估（见《[GPU 监控](/ai/infra/gpu-monitoring/)》《[故障排查](/ai/infra/troubleshooting/)》里要做的事，就是自建路线要养的人）。

**2. 看负载的成长曲线。**
负载是「稳定小规模」（内部问答、文档辅助）→ 一体机；是「明确会涨到集群量级」（多业务线接入、对外服务）→ 一步到位上集群，**别买三台一体机再全部推倒**。

**3. 看谈判地位与数据敏感级。**
一体机的黑盒程度要谈开：硬件到模型栈哪些可审计、日志可导出到客户侧的程度、退出时数据与资产的归属——这三个问题写进合同，才没有后患。

## FDE 的立场

在客户现场谈这个选择时，你的价值是**把三条原则翻译成客户的语言**：有没有人、涨不涨、能不能审计——而不是推销任何一边。结论常常是「先一台一体机跑通业务，负载验证后再谈集群」：**这既是稳妥的技术路线，也天然是客户的分阶段预算方案**（谈单节奏见《[硬件选型](/ai/infra/hardware-choice/)》）。
