## 内网部署的真正难点

不是「装不上」，是**装上之后的依赖链**：一个 pip 包要联网、一个镜像层要拉取、一个时间戳要校验——内网环境里每一条都是一次卡壳。**离线部署的本质是提前把整个依赖链装进你的行李箱。**

## 四大件的离线化

**1. 依赖离线化**
- Python 依赖：在联网环境锁定版本后整包导出，或自建内部 PyPI 镜像；
- 容器镜像：所有镜像先在联网环境 pull/tag/导出（`docker save`），物理带入后导入私有镜像仓库；
- 系统层依赖（驱动、CUDA、容器运行时）：**版本匹配矩阵提前验证好**——这三个的版本冲突是内网部署第一大事故源。

**2. 模型文件分发**
- 权重文件大（几十到几百 GB）：校验和（sha256）比对是必做动作，**拷贝损坏的权重会让服务以诡异方式失败**（能加载、输出乱）；
- 分发通道：加密硬盘物理拷贝 > 内网中转机 > 客户内网文件服务，按客户安全规范选；
- 台账：每个现场跑的模型名、版本、量化档位、校验和——一张表管到底（见《[模型分发](/ai/infra/model-distribution/)》）。

**3. 时间与许可**
- 内网常有 NTP 与证书校验问题：离线环境的时钟漂移会让 HTTPS 和 License 校验失败，部署文档里写死这步检查；
- 模型许可协议：商用授权条款打印带去，客户的合规部门迟早会要。

**4. 升级包管理**
- 每次升级 = 一个完整「依赖 + 模型 + 配置」的离线包 + 回滚包，**成对制作**（见《[滚动升级](/ai/infra/rolling-upgrade/)）；
- 升级演练先在复刻环境跑——内网现场没有「试错再说」的机会。

## 出发前检查清单

- [ ] 依赖锁文件 + 私有镜像源就绪
- [ ] 全部镜像已导出并试导入一次
- [ ] 模型文件校验和通过，含一版备用拷贝
- [ ] 驱动/CUDA/运行时版本矩阵在目标 OS 验证过
- [ ] 部署文档打印版（内网现场手机信号不会配合你）
- [ ] 回滚包成对制作完毕
- [ ] 与客户 IT 约定好内网文件传输方式与审批流程

## 一条经验法则

**离线环境的每一分钟卡壳，都是联网环境没做够演练的利息。** 在公司搭一台复刻内网的机器把全流程走两遍——第二遍不出错，再出发。
