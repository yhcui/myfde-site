## 先立结论

**能不私有化就不私有化。** 公有云 API 是维护成本最低的形态；私有化是用「你买硬件、你管运维」换「数据不出域」。所以这不是「哪个更好」的技术题，是「哪些约束生效」的合规题——按下面的树走一遍。

## 四问决策树

**Q1：客户数据能不能出客户域？**
能出（签了数据协议、已脱敏）→ 回到 API 方案，结束。
**不能（合规硬约束）→ Q2**

**Q2：现场有没有可用网络到云端专线的替代？**
有专线/专有云可用 → 评估专线方案（介于两者之间）。
**完全内网（air-gapped）→ Q3**

**Q3：预算撑得住硬件 + 运维吗？**
私有化的真实成本 = 硬件（一次性）+ 运维人力（持续性）+ **升级折旧（最常被漏算）**——开源模型半年一代，硬件三年一换，这笔账要跟客户摊开算（算账工具见《[显存账本](/ai/infra/vram-ledger/)》《[RAG 成本结构](/ai/infra/rag-cost/)）。
撑不住 → 谈判降级需求或走《[混合部署](/ai/infra/hybrid-deploy/)》。
**撑得住 → Q4**

**Q4：业务对模型能力的要求私有模型能满足吗？**
拿客户真实问题建评估集，把候选开源模型跑一遍——**用数字回答，不用舆论回答**（方法见《[效果验收](/ai/infra/acceptance/)》与《[Evals](/ai/evals-intro/)》）。能满足 → 私有化立项；不能 → 混合部署或再议。

## 三种落位形态与代价

| 形态 | 适用 | 代价 |
|------|------|------|
| **全内网私有化** | 强合规（政务/金融/军工级） | 成本最高、升级最慢、能力受限于开源模型 |
| **专有云/VPC 部署** | 数据可进云但必须隔离 | 平衡型，云厂商代管大部分运维 |
| **混合部署** | 敏感数据 + 通用能力的组合需求 | 架构最复杂，见专篇 |

## 最常被低估的一项成本

**升级折旧。** 私有化不是一次性买断，是签了一份「模型能力冻结在今天的合同」——公有云用户半年后免费享受的下一代模型，私有化现场要重新走一遍选型、验证、升级流程（《[滚动升级](/ai/infra/rolling-upgrade/)》就是为此存在的）。谈判时把这条写进预期，是 FDE 的诚实，也是后续续费的伏笔。

## 小结

决策树的本质：**合规问题先问，成本问题后算，能力问题用评估集回答**。顺序反了（先看技术再问合规）的团队，会在半年后发现方向性返工。
