## 成本的两个生命周期

RAG 的钱分两种花法，混着算永远算不清：

| | 一次性（建库） | 持续（每查询） |
|---|---|---|
| 环节 | 抽取/清洗/嵌入/入库 | 检索/重排/生成 |
| 主成本 | 嵌入计算 + 人力清洗 | 生成 token + 检索算力 |
| 特点 | 随数据量线性，可一次做完 | 随流量线性，天天在烧 |

**新建项目最容易低估左边**（清洗人力按人周算），**运行项目最容易失控右边**（每次查询的隐性 token 翻倍）。

## 持续成本的五段拆解

一次典型查询的成本链：

1. 查询改写/扩展（小模型调用）
2. 嵌入计算（查询向量化）
3. 向量检索（算力）
4. 重排（可选，一次模型调用）
5. **生成（大头）**——检索块的 token 都按输入计费，这是「检索质量=成本」的隐秘通道：**Top-k 给 10 块烂材料，等于每次查询多付一倍 token 且答案更差**——省钱的最好位置常在检索调参（见《[RAG 进阶](/ai/rag-advanced/)》）。

## 四个降本杠杆

1. **缓存**（高频 FAQ 的检索+回答，见《[检索性能账](/ai/infra/retrieval-perf/)》）；
2. **Top-k 调优**：k 从 10 降到 4，输入 token 立减——前提是重排保证质量（用评估集验证）；
3. **提示词缓存**：系统指令+固定说明的长前缀进缓存（见《[Token 经济学](/ai/token-economics/)》）；
4. **分层存储**：冷数据降级到廉价索引档，热数据高性能档——存储账在亿级向量时是笔真钱。

## 该省与不该省

- **该省**：重复劳动（缓存）、无效输入（烂材料）、恒定内容全价计费（缓存前缀）；
- **不该省**：清洗人力（脏数据是复利型负债，见《[数据管道](/ai/infra/data-pipeline/)》）、评估集（省它等于关掉仪表盘）、权限与审计（合规事故的价格没有上限，见《[权限模型](/ai/infra/permission-model/)》）。

## 私有化的账本变体

内网部署把「API 按量」换成「硬件折旧+运维人力」——**成本结构从可变变固定**：流量越大单位成本越低，流量不足就是纯亏。这是《[私有化决策树](/ai/infra/private-deploy-tree/)》里「预算问题」的算账依据。

## 小结

RAG 成本控制的顺序：**先测单次查询的真实成本链，再动杠杆**——五段里你连占比都不知道，优化就只是玄学。相关：《[成本监控](/ai/infra/cost-alerts/)》（运行期的账本仪表）。
