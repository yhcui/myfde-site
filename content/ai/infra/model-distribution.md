## 从「文件」到「资产」的差别

把权重当文件：散落在各台机器的下载目录，名字靠猜，版本靠记忆，出事靠玄学。
把权重当资产：**每个权重有唯一标识、校验和、来源记录、评估快照和生命周期**——这是从 Demo 走向生产在资产维度的那道门（见《[六道门](/fde/demo-to-production/)）。

## 分发纪律三件套

**1. 来源与校验**
- 只从可信源获取（官方发布渠道/内部注册表），**禁止「同事网盘传来的那个版本」**；
- 每次获取即算校验和，入库登记——校验和不符的一律销毁，拷贝损坏是内网部署的经典暗病（见《[离线部署](/ai/infra/air-gapped/)》）；

**2. 版本台账（最少字段）**

| 字段 | 例 |
|------|----|
| 模型名与版本 | qwen-2.5-7b-instruct |
| 量化档位 | AWQ-4bit |
| 校验和 | sha256 |
| 评估快照 | 评估集 v3 通过率 87% |
| 部署位置 | 客户A-机房-节点2 |
| 状态 | 生产 / 灰度 / 已退役 |

**评估快照是这张表最值钱的一列**：换模型/换量化档位时，这个字段让「当时验证过效果」变得可查——没有它的台账只是文件列表（评估方法见《[Evals](/ai/evals-intro/)》）。

**3. 生命周期**
- 旧版本不删，标「已退役」并保留一个恢复周期——回滚包需要它（见《[滚动升级](/ai/infra/rolling-upgrade/)）；
- 台账与真实部署定期对账——现场手工改动漂移是常态，对账才能发现。

## 为什么这值得单独一篇

模型是 AI 系统里**唯一一个「能跑但已经不是你以为的那个」还能不报错的组件**——权重被换过、量化档位记错，服务照样绿灯。台账就是防这种沉默漂移的保险。把它做扎实，后面所有升级、扩点、复盘都有据可查——**这是 FDE 现场管理动作里复利最高的一个**。
