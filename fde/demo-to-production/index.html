从 Demo 到生产：AI 落地检查清单

把一个 AI Demo 变成可以写进客户合同的生产系统，要过六道门：数据、评估、护栏、监控、回退、文档。附每道门的检查项。

这份清单怎么用

「Demo 三周，生产三月」是 AI 落地的常态。多数团队不是能力不够，是不知道 Demo 和生产之间隔着六道门——每道门都是一类事故的保险。这个页面可以当打勾清单用：带去现场，逐门过。

六道门

门一：数据与权限

  • 客户数据的流转路径画清楚：从哪来、存哪、谁可见
  • 敏感数据脱敏或分域，检索层就是权限层
  • 数据更新机制明确（多久同步一次、谁触发）

门二：评估

  • 有 50+ 条真实问题的评估集（见《Evals》）
  • 通过率有基线数字，改动前后可对比
  • 长尾问题有拒答测试（该说「不知道」时会说）

门三：护栏

  • 高危操作走人工确认（见《Guardrails》）
  • 输出有结构校验与来源核对
  • 工具权限最小化，只读与写分离

门四：监控

  • 延迟、失败率、成本按日可见
  • 对话与工具调用全量留痕、可回放
  • 有异常告警，而不是等客户来骂

门五：回退与降级

  • 模型 API 挂了有兜底（重试 / 备用模型 / 人工接管）
  • 新版本可一键回退到上一个稳定版
  • 系统整体可开关——AI 出问题业务不能停摆

门六：文档与移交

  • 给客户的说明书：它能答什么、不能答什么、出问题找谁
  • 给接手工程师的部署文档：架构图、配置、评估怎么跑
  • 和客户对齐过「成功标准」并写进验收

六道门的通过标准

全绿才叫生产。 缺任何一道，系统都属于「演示可用」状态——这句话敢跟客户说清楚，反而是专业度的体现。

和站点其他内容的关系

  • 每道门的深入展开在 AI 栏目的系列文章里；
  • 检查清单与《Evals》《Guardrails》《Token 经济学》互为索引；
  • FDE 的价值主张就一句话：客户没有能力自己过这六道门，这就是 K1 收费的理由（见什么是 FDE）。
